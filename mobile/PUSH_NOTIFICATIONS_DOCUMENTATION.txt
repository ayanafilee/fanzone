================================================================================
                    PUSH NOTIFICATIONS DOCUMENTATION
================================================================================

OVERVIEW:
The FanZone backend uses Firebase Cloud Messaging (FCM) to send push 
notifications to mobile users when new content (news/highlights) is created.

FEATURES:
- Automatic notifications when admin creates news or highlights
- Topic-based subscriptions (users subscribe to their favorite clubs)
- Support for multiple clubs per highlight
- Background notification sending (non-blocking)
- Graceful degradation if FCM fails to initialize

================================================================================
                         HOW IT WORKS
================================================================================

1. TOPIC-BASED NOTIFICATIONS
   - Each club has a topic: "club_{club_id}"
   - Users subscribe to topics for their favorite clubs
   - When content is created for a club, notification sent to that topic
   - All subscribed users receive the notification

2. AUTOMATIC TRIGGERS
   - Admin creates news → Notification sent to club topic
   - Admin creates highlight → Notification sent to all involved club topics
   - Notifications sent in background (doesn't block API response)

3. NOTIFICATION DATA
   - Title: "New news from Arsenal FC" or "New Match Highlight"
   - Body: Content title or match title
   - Data payload: content_id, club_id, type, etc.

================================================================================
                         NOTIFICATION TOPICS
================================================================================

Topic Format:
club_{club_id}

Examples:
- club_507f1f77bcf86cd799439011 (Arsenal FC)
- club_507f1f77bcf86cd799439012 (Chelsea FC)
- all_users (general notifications to all users)

How Topics Work:
1. Mobile app subscribes user to topics based on favorite club
2. Backend sends notification to topic when content is created
3. FCM delivers notification to all subscribed devices

Android (Kotlin):
import com.google.firebase.messaging.FirebaseMessaging

fun subscribeToClub(clubId: String) {
    FirebaseMessaging.getInstance()
        .subscribeToTopic("club_$clubId")
        .addOnCompleteListener { task ->
            if (task.isSuccessful) {
                Log.d("FCM", "Subscribed to club_$clubId")
            }
        }
}

// When user selects favorite club

================================================================================
                         BACKEND IMPLEMENTATION
================================================================================

Notification Service:
internal/notification/fcm.go

Key Functions:

1. NewFCMService()
   - Initializes Firebase Cloud Messaging
   - Loads service account credentials
   - Returns FCM service instance

2. SendToTopic(topic, title, body, data)
   - Sends notification to all users subscribed to topic
   - Used for club-specific notifications

3. NotifyNewContent(clubID, clubName, title, contentID, contentType)
   - Called when admin creates news
   - Sends notification to club topic

4. NotifyNewHighlight(clubIDs, clubNames, matchTitle, highlightID)
   - Called when admin creates highlight
   - Sends notification to all involved club topics

5. NotifyAllUsers(title, body, data)
   - Sends notification to all users
   - Uses "all_users" topic

Admin Handlers:
internal/handlers/admin.go

AdminAddContent():
- Creates news content
- Sends notification to club topic (if club specified)
- Notification sent in background goroutine

AdminAddHighlight():
- Creates highlight
- Sends notification to all involved club topics
- Notification sent in background goroutine

================================================================================
                         TROUBLESHOOTING
================================================================================

Problem: Notifications not received
Solution:
1. Check Firebase project configuration
2. Verify service account key is correct
3. Check mobile app has notification permissions
4. Verify mobile app is subscribed to correct topic
5. Check backend logs for FCM errors

Problem: "Failed to initialize FCM"
Solution:
1. Verify fanzone-c7f93-firebase-adminsdk-fbsvc-7fa1955ab1.json exists
2. Check file path is correct
3. Verify Firebase project is active
4. Check service account has correct permissions

Problem: Notification received but app doesn't navigate
Solution:
1. Check notification data payload
2. Verify navigation logic in mobile app
3. Test with app in foreground, background, and quit states

Problem: Multiple notifications for same content
Solution:
- This is expected for highlights with multiple clubs
- Each club's subscribers receive the notification

Problem: Backend logs show FCM errors
Solution:
1. Check Firebase project quota
2. Verify service account key hasn't expired
3. Check network connectivity
4. Review Firebase console for errors

================================================================================
                         BEST PRACTICES
================================================================================

1. Topic Naming:
   - Use consistent format: "club_{club_id}"
   - Keep topic names lowercase
   - Avoid special characters

2. Notification Content:
   - Keep titles short and clear
   - Use English for notification text
   - Include relevant data in payload

3. Subscription Management:
   - Subscribe when user selects favorite club
   - Unsubscribe when user changes favorite club
   - Handle subscription errors gracefully

4. Testing:
   - Test with app in foreground, background, and quit states
   - Test notification tap navigation
   - Test with multiple clubs subscribed

5. Error Handling:
   - Log FCM errors for debugging
   - Don't block API response if notification fails
   - Gracefully degrade if FCM unavailable

6. Performance:
   - Send notifications in background goroutines
   - Don't wait for notification delivery
   - Keep notification payloads small
