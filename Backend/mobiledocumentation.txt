================================================================================
                        MOBILE APP INTEGRATION GUIDE
================================================================================

RECOMMENDED FLOW FOR PUBLIC APP (NO LOGIN):

1. APP LAUNCH
   - No authentication needed
   - Load default language (device language or English)
   - Navigate to home screen

2. ONBOARDING (OPTIONAL)
   Step 1: GET /api/languages → Show language selector
   Step 2: GET /api/clubs → Show club selector (optional favorite)
   Step 3: Save preferences locally on device
   Step 4: Navigate to home screen

3. HOME SCREEN (MAIN FEED)
   - GET /api/feed/all
   - Display feed items in list/card view
   - Pull-to-refresh to reload feed
   - Tap news item → GET /api/news/:id → Show detail view
   - Tap highlight → GET /api/highlights/:id → Play video

4. CLUBS TAB
   - GET /api/clubs
   - Display clubs grouped by league
   - Tap club → Filter content by club_id
   - GET /api/content?club_id=xxx
   - GET /api/highlights?club_id=xxx

5. WATCH TAB
   - GET /api/watch-platforms
   - Display as grid of platform cards
   - Tap platform → Open URL in browser/webview

6. SETTINGS
   - GET /api/languages → Show language selector
   - Save language preference locally
   - Reload content with new language

7. MULTILINGUAL CONTENT
   - News articles have title/body in en, am, om
   - Display based on user's language preference (stored locally)
   - Example: user selected "am" → show title.am, body.am
   - Fallback to English if translation missing

8. LOCAL STORAGE
   - Store user preferences locally (language, favorite club)
   - No server-side user accounts needed
   - Use SharedPreferences (Android) or UserDefaults (iOS)

================================================================================
                          ADDITIONAL NOTES
================================================================================

1. All timestamps are in ISO 8601 format (UTC)
   Example: "2024-01-15T10:30:00Z"

2. MongoDB ObjectIDs are 24-character hexadecimal strings
   Example: "507f1f77bcf86cd799439011"

3. Image URLs and video URLs are full URLs
   Load them directly in image views or video players

4. Empty/null values:
   - Empty strings: ""
   - Missing fields may not be present in response
   - Check for null/undefined before accessing nested properties

5. Rate limiting: Not currently implemented
   Consider implementing on client side to avoid excessive requests

6. Pagination: Not currently implemented
   All endpoints return complete results
   Consider implementing if performance issues arise

7. Caching recommendations:
   - Cache club list (rarely changes)
   - Cache language list (static)
   - Cache user preferences locally (language, favorite club)
   - Cache feed for short duration (5-10 minutes)
   - Implement pull-to-refresh for manual updates

8. Network error handling:
   - Implement retry logic for failed requests
   - Show user-friendly error messages
   - Provide offline mode with cached content if possible

9. Security best practices:
   - Always use HTTPS in production
   - Validate all data before displaying
   - Sanitize URLs before opening in webview
   - Implement certificate pinning if possible

10. Performance optimization:
    - Load images lazily in feed
    - Implement infinite scroll/pagination for long feeds
    - Compress images before displaying
    - Cache API responses appropriately

The reaction system allows users to react to content (news) and highlights
with 5 different reaction types: like, love, wow, sad, angry

14. ADD OR UPDATE REACTION
--------------------------------------------------------------------------------
Endpoint: POST /api/reactions
Authentication: NOT REQUIRED (Public)

Description:
Add a new reaction or update existing reaction for a user. If the user has
already reacted to this content, their reaction will be updated to the new type.

Request Headers:
Content-Type: application/json

Request Body:
{
  "user_id": "507f1f77bcf86cd799439011",
  "content_type": "news",
  "content_id": "507f1f77bcf86cd799439012",
  "reaction_type": "like"
}

Field Descriptions:
- user_id: MongoDB ObjectID of the user (stored locally on device)
- content_type: Must be "news" or "highlight"
- content_id: MongoDB ObjectID of the content/highlight
- reaction_type: Must be one of: "like", "love", "wow", "sad", "angry"

Success Response (201 Created - New Reaction):
{
  "message": "Reaction added successfully",
  "reaction": {
    "id": "507f1f77bcf86cd799439013",
    "user_id": "507f1f77bcf86cd799439011",
    "content_type": "news",
    "content_id": "507f1f77bcf86cd799439012",
    "reaction_type": "like",
    "created_at": "2026-03-01T10:30:00Z",
    "updated_at": "2026-03-01T10:30:00Z"
  }
}

Success Response (200 OK - Updated Reaction):
{
  "message": "Reaction updated successfully",
  "reaction": {
    "id": "507f1f77bcf86cd799439013",
    "user_id": "507f1f77bcf86cd799439011",
    "content_type": "news",
    "content_id": "507f1f77bcf86cd799439012",
    "reaction_type": "love",
    "created_at": "2026-03-01T10:30:00Z",
    "updated_at": "2026-03-01T10:35:00Z"
  }
}

Error Responses:
400 Bad Request:
{
  "error": "Invalid input: user_id is required"
}
OR
{
  "error": "Invalid input: content_type must be 'news' or 'highlight'"
}
OR
{
  "error": "Invalid input: reaction_type must be one of: like, love, wow, sad, angry"
}

404 Not Found:
{
  "error": "Content not found"
}

500 Internal Server Error:
{
  "error": "Failed to add reaction"
}

Notes:
- If user has no reaction → Creates new reaction
- If user already has a reaction → Updates to new reaction type
- Automatically updates reaction counts on the content/highlight
- User can only have one reaction per content item

Example curl:
curl -X POST http://localhost:8080/api/reactions \
  -H "Content-Type: application/json" \
  -d '{
    "user_id": "507f1f77bcf86cd799439011",
    "content_type": "news",
    "content_id": "507f1f77bcf86cd799439012",
    "reaction_type": "like"
  }'

REACTION TYPES AND EMOJIS:

- wow: 😮
- sad: 😢
- angry: 😠

USER ID MANAGEMENT:
Since the app has no login, generate a unique user_id on first launch:
1. Generate UUID or use device ID
2. Store in local storage (SharedPreferences/UserDefaults)
3. Use this ID for all reaction API calls

RECOMMENDED UI FLOW:

1. DISPLAY REACTIONS ON CONTENT
   When showing news or highlight:
   - GET /api/reactions/:type/:id/counts → Display reaction counts
   - GET /api/reactions/:type/:id/me?user_id=xxx → Highlight active reaction

2. USER TAPS REACTION BUTTON
   Scenario A: User has no reaction
   - POST /api/reactions → Add new reaction
   - Update UI to show active reaction
   - Increment count locally (optimistic update)

   Scenario B: User taps same reaction (toggle off)
   - DELETE /api/reactions/:type/:id?user_id=xxx → Remove reaction
   - Update UI to show no active reaction
   - Decrement count locally

   Scenario C: User taps different reaction
   - POST /api/reactions → Update to new reaction
   - Update UI to show new active reaction
   - Adjust counts locally (decrement old, increment new)

3. OPTIMISTIC UI UPDATES
   Update UI immediately when user reacts, then sync with backend:
   ```javascript
   const handleReaction = async (reactionType) => {
     // Optimistic update
     if (userReaction === reactionType) {
       setUserReaction(null);
       decrementCount(reactionType);
     } else {
       if (userReaction) decrementCount(userReaction);
       setUserReaction(reactionType);
       incrementCount(reactionType);
     }
     
     // Sync with backend
     try {
       if (userReaction === reactionType) {
         await removeReaction(contentType, contentId, userId);
       } else {
         await addReaction(userId, contentType, contentId, reactionType);
       }
     } catch (error) {
       // Revert optimistic update on error
       revertChanges();
       showError("Failed to update reaction");
     }
   };
   ```

   Display horizontal row of reaction buttons:
   ```
   [👍 45] [❤️ 23] [😮 12] [😢 3] [😠 1]
   ```
   - Active reaction is highlighted/colored
   - Inactive reactions are gray
   - Show count next to each emoji
   - Tap to add/remove/change reaction

5. REACTION DETAILS VIEW (OPTIONAL)
   Show who reacted:
   - GET /api/reactions/:type/:id/users?reaction_type=like
   - Display list: "John, Sarah, Mike, and 42 others liked this"

EXAMPLE IMPLEMENTATION (React Native):

```javascript
import React, { useState, useEffect } from 'react';
import { View, TouchableOpacity, Text } from 'react-native';

const ReactionBar = ({ contentType, contentId, userId }) => {
  const [userReaction, setUserReaction] = useState(null);
  const [counts, setCounts] = useState({
    like: 0, love: 0, wow: 0, sad: 0, angry: 0
  });

  useEffect(() => {
    loadReactions();
  }, []);

  const loadReactions = async () => {
    // Get user's reaction
    const userResp = await fetch(
      `${API_URL}/reactions/${contentType}/${contentId}/me?user_id=${userId}`
    );
    const userData = await userResp.json();
    setUserReaction(userData.reaction?.reaction_type || null);

    // Get reaction counts
    const countsResp = await fetch(
      `${API_URL}/reactions/${contentType}/${contentId}/counts`
    );
    const countsData = await countsResp.json();
    setCounts(countsData.counts);
  };

  const handleReaction = async (reactionType) => {
    const isRemoving = userReaction === reactionType;

    // Optimistic update
    if (isRemoving) {
      setUserReaction(null);
      setCounts(prev => ({ ...prev, [reactionType]: prev[reactionType] - 1 }));
    } else {
      if (userReaction) {
        setCounts(prev => ({ ...prev, [userReaction]: prev[userReaction] - 1 }));
      }
      setUserReaction(reactionType);
      setCounts(prev => ({ ...prev, [reactionType]: prev[reactionType] + 1 }));
    }

    // Sync with backend
    try {
      if (isRemoving) {
        await fetch(
          `${API_URL}/reactions/${contentType}/${contentId}?user_id=${userId}`,
          { method: 'DELETE' }
        );
      } else {
        await fetch(`${API_URL}/reactions`, {
          method: 'POST',
          headers: { 'Content-Type': 'application/json' },
          body: JSON.stringify({
            user_id: userId,
            content_type: contentType,
            content_id: contentId,
            reaction_type: reactionType
          })
        });
      }
    } catch (error) {
      // Revert on error
      loadReactions();
      alert('Failed to update reaction');
    }
  };

  const reactions = [
    { type: 'like', emoji: '👍' },
    { type: 'love', emoji: '❤️' },
    { type: 'wow', emoji: '😮' },
    { type: 'sad', emoji: '😢' },
    { type: 'angry', emoji: '😠' }
  ];

  return (
    <View style={{ flexDirection: 'row', gap: 10 }}>
      {reactions.map(({ type, emoji }) => (
        <TouchableOpacity
          key={type}
          onPress={() => handleReaction(type)}
          style={{
            padding: 8,
            borderRadius: 20,
            backgroundColor: userReaction === type ? '#e3f2fd' : '#f5f5f5'
          }}
        >
          <Text>
            {emoji} {counts[type]}
          </Text>
        </TouchableOpacity>
      ))}
    </View>
  );
};

export default ReactionBar;
```

- Use optimistic updates for better UX

- Retry failed requests automatically
- Handle offline mode gracefully
