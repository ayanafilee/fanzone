================================================================================
                              API ENDPOINTS
================================================================================

All endpoints are PUBLIC (no authentication required):

1. POST /api/reactions
   - Add or update user's reaction
   - Body: { user_id, content_type, content_id, reaction_type }

2. DELETE /api/reactions/:content_type/:content_id?user_id=xxx
   - Remove user's reaction

3. GET /api/reactions/:content_type/:content_id/me?user_id=xxx
   - Get user's current reaction

4. GET /api/reactions/:content_type/:content_id/counts
   - Get reaction counts for content

5. GET /api/reactions/:content_type/:content_id/users
   - Get list of users who reacted
   - Optional: ?reaction_type=like&limit=50&offset=0

================================================================================
                              SYSTEM ARCHITECTURE
================================================================================

Flow: Mobile App → API Endpoint → Handler → Repository → MongoDB

1. User taps reaction button in mobile app
2. App calls POST /api/reactions
3. Handler validates input
4. Repository checks if reaction exists
5. If exists: Update reaction type and counts
6. If not: Create new reaction and increment count
7. Return success response to app
8. App updates UI
