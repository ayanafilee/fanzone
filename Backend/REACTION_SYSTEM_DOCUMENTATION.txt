# REACTION SYSTEM DOCUMENTATION

## Overview
The reaction system allows users to react to content (news) and highlights with 5 different reaction types:
- like 👍
- love ❤️
- wow 😮
- sad 😢
- angry 😠

Users can add, update, or remove their reactions. The system tracks reaction counts and which users reacted with each type.

## Database Models

### Reaction Model
```json
{
  "_id": "ObjectID",
  "user_id": "string",
  "content_type": "news | highlight",
  "content_id": "string",
  "reaction_type": "like | love | wow | sad | angry",
  "created_at": "timestamp",
  "updated_at": "timestamp"
}
```

### Content/Highlight Models (Updated)
Both Content and Highlight models now include a `reactions` field:
```json
{
  "reactions": {
    "like": 0,
    "love": 0,
    "wow": 0,
    "sad": 0,
    "angry": 0
  }
}
```

## API Endpoints

### 1. Add or Update Reaction
**Endpoint:** `POST /api/reactions`
**Authentication:** Public (no auth required)
**Description:** Add a new reaction or update existing reaction for a user

**Request Body:**
```json
{
  "user_id": "507f1f77bcf86cd799439011",
  "content_type": "news",
  "content_id": "507f1f77bcf86cd799439012",
  "reaction_type": "like"
}
```

**Validation Rules:**
- `user_id`: Required, valid MongoDB ObjectID
- `content_type`: Required, must be "news" or "highlight"
- `content_id`: Required, valid MongoDB ObjectID
- `reaction_type`: Required, must be one of: "like", "love", "wow", "sad", "angry"

**Success Response (201 Created):**
```json
{
  "message": "Reaction added successfully",
  "reaction": {
    "id": "507f1f77bcf86cd799439013",
    "user_id": "507f1f77bcf86cd799439011",
    "content_type": "news",
    "content_id": "507f1f77bcf86cd799439012",
    "reaction_type": "like",
    "created_at": "2026-03-01T10:30:00Z",
    "updated_at": "2026-03-01T10:30:00Z"
  }
}
```

**Success Response (200 OK - Updated):**
```json
{
  "message": "Reaction updated successfully",
  "reaction": {
    "id": "507f1f77bcf86cd799439013",
    "user_id": "507f1f77bcf86cd799439011",
    "content_type": "news",
    "content_id": "507f1f77bcf86cd799439012",
    "reaction_type": "love",
    "created_at": "2026-03-01T10:30:00Z",
    "updated_at": "2026-03-01T10:35:00Z"
  }
}
```

**Error Responses:**
- 400 Bad Request: Invalid input data
- 404 Not Found: Content not found
- 500 Internal Server Error: Database error

**Behavior:**
- If user has no reaction on this content → Creates new reaction
- If user already has a reaction on this content → Updates to new reaction type
- Automatically updates reaction counts on the content/highlight

---

### 2. Remove Reaction
**Endpoint:** `DELETE /api/reactions/:content_type/:content_id`
**Authentication:** Public (no auth required)
**Description:** Remove a user's reaction from content

**URL Parameters:**
- `content_type`: "news" or "highlight"
- `content_id`: MongoDB ObjectID of the content

**Query Parameters:**
- `user_id`: Required, MongoDB ObjectID of the user

**Example:**
```
DELETE /api/reactions/news/507f1f77bcf86cd799439012?user_id=507f1f77bcf86cd799439011
```

**Success Response (200 OK):**
```json
{
  "message": "Reaction removed successfully"
}
```

**Error Responses:**
- 400 Bad Request: Missing or invalid user_id
- 404 Not Found: Reaction not found
- 500 Internal Server Error: Database error

**Behavior:**
- Removes the user's reaction from the database
- Decrements the reaction count on the content/highlight
- If reaction doesn't exist, returns 404

### 3. Get User's Reaction
**Endpoint:** `GET /api/reactions/:content_type/:content_id/me`
**Authentication:** Public (no auth required)
**Description:** Get the current user's reaction on specific content

**URL Parameters:**
- `content_type`: "news" or "highlight"
- `content_id`: MongoDB ObjectID of the content

**Query Parameters:**
- `user_id`: Required, MongoDB ObjectID of the user

**Example:**
```
GET /api/reactions/news/507f1f77bcf86cd799439012/me?user_id=507f1f77bcf86cd799439011
```

**Success Response (200 OK):**
```json
{
  "reaction": {
    "id": "507f1f77bcf86cd799439013",
    "user_id": "507f1f77bcf86cd799439011",
    "content_type": "news",
    "content_id": "507f1f77bcf86cd799439012",
    "reaction_type": "like",
    "created_at": "2026-03-01T10:30:00Z",
    "updated_at": "2026-03-01T10:30:00Z"
  }
}
```

**Response (200 OK - No Reaction):**
```json
{
  "reaction": null
}
```

**Error Responses:**
- 400 Bad Request: Missing or invalid user_id
- 500 Internal Server Error: Database error

**Use Case:**
- Check if user has already reacted to content
- Display the user's current reaction in the UI
- Highlight the active reaction button

**URL Parameters:**

**Error Responses:**

- 500 Internal Server Error: Database error

- Show most popular reactions
- Calculate total engagement

### 5. Get Users Who Reacted
**Endpoint:** `GET /api/reactions/:content_type/:content_id/users`
**Authentication:** Public (no auth required)
**Description:** Get list of users who reacted with a specific reaction type

**URL Parameters:**
- `content_type`: "news" or "highlight"
- `content_id`: MongoDB ObjectID of the content

**Query Parameters:**
- `reaction_type`: Optional, filter by specific reaction ("like", "love", "wow", "sad", "angry")
- `limit`: Optional, number of users to return (default: 50, max: 100)
- `offset`: Optional, pagination offset (default: 0)

**Examples:**
```
GET /api/reactions/news/507f1f77bcf86cd799439012/users?reaction_type=like
GET /api/reactions/highlight/507f1f77bcf86cd799439012/users?limit=20&offset=0
GET /api/reactions/news/507f1f77bcf86cd799439012/users
```

**Success Response (200 OK):**
```json
{
  "content_type": "news",
  "content_id": "507f1f77bcf86cd799439012",
  "reaction_type": "like",
  "users": [
    {
      "user_id": "507f1f77bcf86cd799439011",
      "reaction_type": "like",
      "reacted_at": "2026-03-01T10:30:00Z"
    },
    {
      "user_id": "507f1f77bcf86cd799439014",
      "reaction_type": "like",
      "reacted_at": "2026-03-01T10:25:00Z"
    }
  ],
  "total": 45,
  "limit": 50,
  "offset": 0
}
```

**Error Responses:**
- 400 Bad Request: Invalid reaction_type
- 500 Internal Server Error: Database error

**Use Case:**
- Show "John, Sarah, and 43 others reacted with ❤️"
- Display list of users who liked content
- Social proof and engagement metrics

### Handle User Reactions
```javascript
const handleReaction = async (reactionType) => {
  const userId = await getUserId(); // Get from local storage
  const contentType = "news"; // or "highlight"
  const contentId = content.id;
  
  // If user clicks same reaction, remove it
  if (userReaction === reactionType) {
    await removeReaction(contentType, contentId, userId);
    setUserReaction(null);
  } else {
    // Add or update reaction
    await addReaction(userId, contentType, contentId, reactionType);
    setUserReaction(reactionType);
  }
  
  // Refresh reaction counts
  await fetchReactionCounts(contentType, contentId);
};
```

### API Call Examples

#### Add Reaction
```javascript
const addReaction = async (userId, contentType, contentId, reactionType) => {
  const response = await fetch('https://your-api.com/api/reactions', {
    method: 'POST',
    headers: {
      'Content-Type': 'application/json',
    },
    body: JSON.stringify({
      user_id: userId,
      content_type: contentType,
      content_id: contentId,
      reaction_type: reactionType
    })
  });
  
  if (!response.ok) {
    throw new Error('Failed to add reaction');
  }
  
  return await response.json();
};
```

#### Remove Reaction
```javascript
const removeReaction = async (contentType, contentId, userId) => {
  const response = await fetch(
    `https://your-api.com/api/reactions/${contentType}/${contentId}?user_id=${userId}`,
    { method: 'DELETE' }
  );
  
  if (!response.ok) {
    throw new Error('Failed to remove reaction');
  }
  
  return await response.json();
};
```

#### Get User's Reaction
```javascript
const getUserReaction = async (contentType, contentId, userId) => {
  const response = await fetch(
    `https://your-api.com/api/reactions/${contentType}/${contentId}/me?user_id=${userId}`
  );
  
  if (!response.ok) {
    throw new Error('Failed to get user reaction');
  }
  
  const data = await response.json();
  return data.reaction?.reaction_type || null;
};
```

#### Get Reaction Counts
```javascript
const getReactionCounts = async (contentType, contentId) => {
  const response = await fetch(
    `https://your-api.com/api/reactions/${contentType}/${contentId}/counts`
  );
  
  if (!response.ok) {
    throw new Error('Failed to get reaction counts');
  }
  
  return await response.json();
};
```

## User Flow Examples

### Scenario 1: User Reacts to News
1. User opens news article
2. App calls `GET /api/reactions/news/{id}/me?user_id={userId}` to check existing reaction
3. App calls `GET /api/reactions/news/{id}/counts` to get all reaction counts
4. User taps "like" button
5. App calls `POST /api/reactions` with reaction data
6. Backend creates reaction and updates content reaction count
7. App updates UI to show active "like" button and incremented count

### Scenario 2: User Changes Reaction
1. User has already reacted with "like"
2. User taps "love" button
3. App calls `POST /api/reactions` with new reaction type
4. Backend updates existing reaction from "like" to "love"
5. Backend decrements "like" count and increments "love" count
6. App updates UI to show active "love" button

### Scenario 3: User Removes Reaction
1. User has reacted with "like"
2. User taps "like" button again (toggle off)
3. App calls `DELETE /api/reactions/news/{id}?user_id={userId}`
4. Backend removes reaction and decrements "like" count
5. App updates UI to show no active reaction

## Migration Notes

### Initialize Reactions Field
For existing content and highlights in the database, you need to initialize the reactions field:

```javascript
// MongoDB shell commands
db.content.updateMany(
  { reactions: { $exists: false } },
  { $set: { reactions: { like: 0, love: 0, wow: 0, sad: 0, angry: 0 } } }
)

db.highlights.updateMany(
  { reactions: { $exists: false } },
  { $set: { reactions: { like: 0, love: 0, wow: 0, sad: 0, angry: 0 } } }
)
```

## Best Practices

1. **Optimistic UI Updates**: Update UI immediately when user reacts, then sync with backend
2. **Debouncing**: If user rapidly changes reactions, debounce API calls
3. **Caching**: Cache reaction counts and user reactions to reduce API calls
4. **Error Handling**: Show user-friendly messages if reaction fails
5. **Offline Support**: Queue reactions when offline, sync when online
6. **Rate Limiting**: Consider rate limiting on backend to prevent spam
